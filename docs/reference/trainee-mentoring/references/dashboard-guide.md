# דשבורד מעקב חניכים — הוראות עדכון (עבור Claude)

דשבורד: [כתובת הדשבורד — לרשום אחרי ההקמה] (סוג Dashboard)
מונחים ואיך לפרק הודעות: claude/glossary.md · שמות תרצים: claude/tests-catalog.md

## עיקרון מספר 1: הטקסט של המפקד נשמר כמו שהוא
- כל עדכון נרשם **מילה במילה, כפי שהמפקד כתב** — בתיק החניך ובציר הזמן. בלי לנסח מחדש, בלי לקצר, בלי "לתקן".
- שמות תרצים, קיצורים ומונחים לא מוכרים נרשמים כמו שהם. אי-הבנה היא לא סיבה לא לתעד.
- אם משהו לא ברור — לתעד קודם, ואז לשאול. את ההבהרה מוסיפים אחר כך כהערה נפרדת, לא במקום המקור.
- הניתוח של Claude (הערכות מיומנויות, סטטוס, תמונת מצב) הוא תוספת שמסומנת ככזו — לעולם לא תחליף לטקסט המקורי.
- חריג יחיד: בדשבורד, משפט עם פרט אישי רגיש מוחלף ב-"[פרט אישי — בתיק]". בתיק החניך הכל נשמר במלואו.

## איך מעדכנים
1. קוראים את ה-dataset הרלוונטי מהמאגר (ArtifactData get, collection "datasets") כדי לקבל את ה-url הנוכחי.
2. מורידים את הקובץ הקיים (Artifact read עם path = מזהה ה-blob), מוסיפים/מעדכנים שורות.
3. מעלים כקובץ JSON חדש (Artifact publish, asset:true) ומעדכנים את datasets/<id>: source {kind:"file", url, name, format:"json"}, updated {at, by:"Claude"}.
4. כל שורה מקבלת seq — מספר רץ לפי סדר הכתיבה (גבוה מכל seq קיים). כך פריטים מאותו תאריך מוצגים בסדר הנכון.
(אם סוג ה-Dashboard מחזיר הוראות אחרות לעדכון נתונים — לפעול לפיהן ולעדכן את הסעיף הזה.)

## הקבצים והשדות
- trainees: {trainee, status: "good"|"watch"|"concern", snapshot, focus, improve, keep, eval_stage, updated:"YYYY-MM-DD"}
  - snapshot ו-focus — הניסוח של Claude. בקשה מפורשת של המפקד לשיחה הבאה נכתבת ב-focus במילים שלו, לפני ההצעה של Claude.
  - improve / keep — נקודות שיפור ושימור של המפקד, כפי שכתב. הצעות של Claude מסומנות "(הצעה)".
  - eval_stage — שלב בתהליך הערכה: "רף מקס" / "רף רמד" / "רף מפקד היחידה" / "הדחה", או ריק. מוצג כתגית ליד השם. משנים רק כשהמפקד אומר.
- talks: {trainee, date, seq, topics, followup} — topics = הטקסט המקורי של המפקד (בלי משפטים רגישים).
- tests: {id, trainee, date, seq, subject, test, score (מספר או null), sked (bool), self, note}
  - test = שם קנוני מהקטלוג; note = הטקסט המקורי המלא.
  - self = ההערכה העצמית של החניך מהרמ"ת (למשל "עובר" / "לא עובר"), אם ידועה.
- skills: {trainee, date, seq, skill, level, context}
  - level במילים: "מתקשה" / "מסתדר" / "חזק" (או 1–5 אם המפקד בחר מספרים בהקמה — להחליף כאן בהתאם).
  - "משתפר" / "נסוג" לא נרשמים — הדשבורד מחשב אותם מהשוואה להערכה הקודמת באותה מיומנות.
  - context = שם האירוע כפי שמופיע בציר הזמן (שם תרץ קנוני, Padens, סוציו...), כדי שההערכה תוצמד לאירוע.
  - מעריכים רק מיומנות שבאמת עולה מהטקסט.
- notes: {trainee, date, seq, kind, title, text} — text = הטקסט המקורי. kind: "תצפית" / "פרויקט" / "צוות" / "התנהלות" / "רמ"ת" / "שיפור/שימור" / "שאיפות" / "סוציו" / "רקע" / "לשיחה הבאה" / "תהליך הערכה" / "הבהרה".

שמות המיומנויות הקבועים:
- מקצועיות/אישיות: קריאת תיק אפיון, הבנת הבעיה, אלגוריתמיקה, תכנון מקדים, מעבר לביצוע, דיבאג, חזרה לתכנון, ביקורתיות עצמית, התמודדות עם לחץ, השקעה ומוטיבציה.
- בין-אישיות: עבודת צוות, תקשורת, קבלת ביקורת, אחריות ואמינות, עזרה לאחרים.

## מה מציג הדשבורד
- מבט צוות: מי צריך שיחה (מד ימים), מדדים, כרטיס לכל חניך (עם תגית תהליך הערכה ליד השם), לוח מיומנויות (מתקשה / משתפר / מסתדר / חזק לכל חניך), חולשות משותפות (מיומנות שיותר מחניך אחד מתקשה בה), ותיעודים אחרונים עם סינון לפי סוג.
- לחיצה על כרטיס חניך: תמונת מצב, שיפור/שימור, מיומנויות לאורך זמן (רצף ההערכות), וציר זמן של כל התרצים, השיחות והתצפיות.
- מצב כהה/בהיר: כפתור בראש הדשבורד; ברירת המחדל לפי המכשיר.

## ספי שיחות
עד 10 ימים — ירוק · 11–14 — צהוב · מעל 14 או טרם נערכה — אדום. (להתאים ליעד השיחות של המפקד.)

## מה לא נכנס לדשבורד
פרטים אישיים רגישים (בריאות, משפחה, מצוקה) נשמרים רק בתיק החניך במסמכי ה-Project, לא בדשבורד.
